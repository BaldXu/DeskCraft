# DeskCraft 项目计划

> 个人自用的安卓桌面小组件工坊 —— 目标是做一个"属于自己的 KWGT"。
> 本文档为权威规划，开工前必读。

## 一、项目定位

一句话：**一个装在自己手机（小米 + Magisk root）上的"桌面小组件工坊"**。
官方组件丑、主题商店收费，于是自己用 Flutter 画组件、自己搭编辑器，像 KWGT 一样可视化拼装，最终放上小米桌面。只服务自己一个人。

## 二、背景与灵感

- 用户在用小米手机，桌面可添加第三方 App 的组件（标准 Android AppWidget）。
- 想自写：时钟、日历、系统参数（温度、CPU 频率）等组件，App 作为这堆组件的管理器。
- **真正的灵感来源是 KWGT（Kustom Widget Maker）**：允许在 App 内可视化编辑组件——图层画布 + 公式系统 + 全局变量 + 触控 + 按需刷新。
- 因此目标升级为：**用 Flutter 自研一个"KWGT 子集"引擎**，而非预置固定组件。

## 三、技术选型（已定案）

| 层 | 选型 | 理由 |
|----|------|------|
| 管理器 / 编辑器 UI | **Flutter**（3.44.8，G:\Code\env\flutter39） | 自定义绘制强，适合编辑器 + 预览；用户熟悉，且"反正基本都是 AI 写" |
| 桌面 widget 桥 | **home_widget 0.10.0**（需 Flutter ≥3.38.1 ✅） | 成熟：saveWidgetData / updateWidget / renderFlutterWidget / interactivity 回调 |
| root 数据源 | **libsu**（topjohnwu 开源库） | Magisk 授权一次，静默读 sysfs + 自加白名单 |
| 定时/刷新 | **AlarmManager + 系统广播** | widget 刷新节流由系统控制，需精确闹钟硬刷到秒/分级 |
| 本地存储 | drift / sqflite + 全局变量 JSON | 组件配置、用户预设 |

关键认知（必须接受）：**桌面 widget 的"皮"是原生 RemoteViews，不是 Flutter 渲染的**。
Flutter 负责：数据计算、UI 样式、配置/编辑器、把内容渲染成位图喂给 widget 壳。
原生侧只有极薄壳：每 widget 一个 provider + 布局 XML + libsu 读取桥。

## 四、系统架构

```
┌─────────────────────────────────────────────────┐
│  App 本体（Flutter）                              │
│  ├─ 组件工坊首页：组件卡片列表 + 实时预览          │
│  ├─ 组件编辑器（KWGT 式）：图层画布/属性面板/预览   │
│  ├─ 配置页：主题色/字体/深色/内容项开关            │
│  └─ root 状态页 + 悬浮窗开关                      │
├─────────────────────────────────────────────────┤
│  Dart 数据层                                      │
│  ├─ 公式引擎：解析 $...$ → AST → 求值（自研）      │
│  ├─ 变量提供器：时间/电池/温度/频率/内存/日历      │
│  └─ 渲染器：图层模型 → 位图（route A 起步）        │
├─────────────────────────────────────────────────┤
│  原生壳（Kotlin + XML，极薄）                      │
│  ├─ AppWidgetProvider（每 widget 一个，模板化）   │
│  ├─ libsu 桥：读 sysfs + 白名单自授权             │
│  └─ AlarmManager 调度 / 广播监听（DATE_CHANGED）  │
└─────────────────────────────────────────────────┘
```

## 五、关键技术决策与已知坑

1. **widget 刷新节流（平台硬限制）**：updatePeriodMillis 最小 30 分钟、WorkManager 15 分钟、精确闹钟可到秒级但需白名单保活。时钟用系统 TextClock（零功耗自动走秒）；监控组件 30s~1min 刷新；秒级实时 → 悬浮窗形态。
2. **温度/CPU 频率必须 root**：无 root 时 SELinux 屏蔽 sysfs（Android 10+ 大多读不到）。root 后 `su -c cat /sys/...` 全可读。用户手机是 **Magisk（非 KernelSU）**。
3. **小米后台杀进程**：root 后 app 启动时自执行白名单：
   - `dumpsys deviceidle whitelist +包名`
   - `appops set 包名 RUN_IN_BACKGROUND allow`
   - `appops set 包名 SYSTEM_ALERT_WINDOW allow`
4. **渲染路线：A 起步**（全 widget 位图渲染塞 ImageView）—— 先跑通闭环，交互简单；B（图层映射原生控件）留作优化方向。
5. **秒级实时只有悬浮窗能做**：widget 上即使 root 也不优雅（每秒唤醒+渲染耗电）。
6. 深色模式/多尺寸适配 → onAppWidgetOptionsChanged 处理。
7. 中文农历 → lunar 包。

## 六、组件清单（V1）

1. 数字时钟（TextClock 驱动，样式可配）—— 全链路验证组件
2. 日历（农历/节气/纪念日，翻日即时刷）
3. 系统监控 widget（电池温度/CPU 频率/占用/内存，30s~1min 刷新，高温红色警示）
4. 实时监控悬浮窗（秒级，root 自动授权，可拖拽/调透明度）
5. 编辑器产出的自定义组件（KWGT 子集）

## 七、里程碑

- **M1 骨架**：Flutter 工程 + home_widget 接通 + 数字时钟上桌（验证：桌面添加→更新→点击全链路）
- **M2 root 验证**：libsu 接入 + 真机读温度/频率成功（最关键未知数，尽早验证）
- **M3 管理器**：组件卡片页 + 配置页 + 主题系统
- **M4 日历 + 监控 widget**（系统监控 ✅ 已上桌，剩余：日历组件）
- **M5 悬浮窗**
- **M6 KWGT 子集编辑器**：公式引擎 + 图层画布 + 全局变量 + 触控 + 预览 → 位图上桌

分层交付原则：**严格按里程碑推进，先把"编辑器→公式→上桌→刷新→点击"闭环跑通，不要一上来复刻 KWGT 全部**。

## 七.5、App 交互架构（已定案）

三层导航，首页保持轻量、随组件增多不失控：

1. **首页（类目入口）**：仅展示组件类目卡（数字时钟 / 系统监控）+ 规划中占位卡（日历 / 组件编辑器），不含实时预览。
2. **类目页（组件库）**：该类目下已完成组件的成品卡（实时预览 + 已上桌徽章 + 一键添加到桌面），可选数据源状态面板（如监控类的 Root 探测）。
3. **配置页**：单组件的样式/行为配置（ClockConfigPage / MonitorConfigPage）。

支撑代码：`WidgetPinService`（上桌检测/一键添加）、`WidgetEntryCard`（成品卡通用组件），新增组件按"类目页成品卡 + 配置页"模式挂接即可。

## 八、风险

- root 读取在部分机型路径不同 → 真机实测，读不到就隐藏该项
- 公式引擎工作量最大 → V1 做核心子集（时间格式化/字符串/条件/四则/系统变量/全局变量）
- MIUI 版本差异 → 以用户真机为准调试
- 秒级刷新耗电 → 悬浮窗独立开关，widget 保持低刷新频率

## 九、开发约定

- 遵循 three-phase-code-dev 三阶段，默认阶段一（需求明确时跳过直接实现）
- 改完 UI 自动拉 web 服务给用户看
- git commit 必须用户明确要求才做，禁止 push
- 文档优先更新本文件 + docs/REQUIREMENTS.md

## 十、远期构想（仅记录，暂不实施）

**组件自定义系统（绘画创作式编辑体验）**——M6 编辑器的雏形方向：

- 用户可在画布上自由摆放信息模块（时间控件、电池温度、CPU、内存等），通过**拖拽调整位置、拼接组合**定制专属桌面组件布局，体验类似绘画创作。
- 模块 = 可复用"零件"（预览即所得），画布产物序列化为布局 JSON，喂给原生壳渲染成位图上桌。
- 落地路径：先在配置页做"模块显隐 + 顺序调整"的轻量版，验证数据模型后再升级为自由拖拽画布，最终并入 M6 图层系统。
